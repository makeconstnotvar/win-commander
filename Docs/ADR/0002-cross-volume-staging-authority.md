# ADR 0002: Cross-volume reviewed Copy requires isolated staging authority

> Status: accepted
> Date: 2026-08-03
> Scope: future Native-to-Native cross-volume reviewed create-only Copy

## Context

ADR 0001 deliberately supports only an exact same-volume APFS clone. A cross-volume Copy needs a complete staged payload before the destination name becomes visible, then a create-only publication bound to that exact staged object. `NativeCreateCopy` is a characterization capsule, not a production candidate: it records that POSIX validation of a named stage and `renameatx_np(..., RENAME_EXCL)` are separate namespace operations. A same-UID process can replace the stage name after inode validation and before rename.

Random names, a `0700` directory, `O_NOFOLLOW`, descriptor rechecks, `flock`, and `RENAME_EXCL` do not bind the source stage inode to the final publish step. The current journal has no descriptor- or inode-bound authority to delete a retained stage after restart. Reusing that capsule in the reviewed `CopyAs` path would weaken the clone transaction's mutation guarantee.

## Decision

The production reviewed transaction remains fail closed for different volumes. `SameVolumeClone` denotes only the existing same-volume clone scope; `CrossVolumeStaged` is selectable only with an available production staging authority. Without it, different volumes retain the established legacy operation route.

The future first cross-volume scope must be one regular file, create-only, exact same `NativeHost`, and two distinct internal, local, writable APFS volumes. External, removable, ejectable, network, read-only, unknown-permission, and unavailable volumes remain unsupported.

That service must be a narrow signed helper with a distinct staging authority, protected roots on each participating volume, a bounded manifest/lease and descriptor-bound cleanup. Its transaction must:

1. validate the exact reviewed source and destination-parent descriptors without namespace mutation in Begin;
2. create a helper-owned stable source snapshot and a helper-owned destination stage;
3. copy permitted data and metadata into the stage, synchronize it, then revalidate source, destination parent, absent destination and staged identity;
4. perform the sole user-visible create-only publication through a helper-held atomic namespace operation;
5. no-follow reopen and verify destination identity/metadata, then order `fsync(destination) → fsync(parent) → F_FULLFSYNC(destination)`;
6. retain all orphan-stage cleanup authority in the helper and report only conservative `NotPublished`, `Published`, or `Unknown` results to the existing transaction/journal path.

No user-facing journal recovery action may delete a staging pathname.

### Protocol boundary V1

`RoutedIO/CrossVolumeStagingProtocol` defines the typed, VFS-independent ABI before the helper implementation. Every request and reply carries protocol version 1 and a nonzero 128-bit correlation ID. A Begin claim carries complete scalar source and destination-parent seals plus one bounded byte destination component; its private XPC codec accepts only that grammar and carries exactly the two duplicated descriptor rights beside the value claim. The component accepts 1–255 bytes and represents an APFS name, while a helper-minted opaque 256-bit lease binds the Begin correlation to exactly one Commit or Abort request. Completion replies preserve the existing conservative `NotPublished`/`Published`/`Unknown` result and independent filesystem-sync evidence.

The public protocol contains neither user paths nor helper artifact names. The private codec and injectable VFS client now duplicate the two reviewed FDs, reject malformed or mismatched replies, and retain a granted lease through exactly one terminal request or conservative `Unknown`. `CrossVolumeStagingHelperV1` authenticates the signed peer before strict V1 decode, then consumes the two owned FDs into private `ValidatedBegin` only after setting and checking `FD_CLOEXEC`, rejecting writable rights and exact-`fstat` revalidating every scalar source/destination-parent seal. It maps invalid claims, source drift, destination-parent drift and helper failures to typed Begin rejection and otherwise remains inert with `Unsupported`/conservative `Unknown`. Its bounded helper-private `LeaseStore` accepts only move-only `ValidatedBegin`, uses `SecRandomCopyBytes`, binds one non-reusable correlation to one authenticated peer and retains the two validated descriptor rights until one terminal take or peer revoke; the authenticated dispatcher now reaches it only through the `LeaseLifecycle` increment below. The helper-private `ProtectedRootLedger` admits a root-owned `0700` directory only through a borrowed root FD and holds one process-local ledger owner per sealed root identity. It durably writes each random artifact ID, root seal, correlation and role into a primary `0600` one-link reservation manifest, rejects durable duplicate header/role claims, and bounds the root to 16 canonical primary reservation records, including malformed records after restart. `MaterializeEmptyAndSeal` is a helper-private root-only writer: under an exact reservation it creates the canonical private empty artifact with mode `0600` and one link, synchronizes `artifact → root → F_FULLFSYNC(artifact)`, then exclusively appends a `0600` sealed companion manifest while preserving the primary reservation manifest. `SourceSnapshotWriter` additionally consumes only a committed helper-private terminal lease, rejects `Abort` before cancellation or reservation, requires its protected root on `request.source.device`, revalidates the exact read-only source descriptor before reservation, before artifact creation, after positional `pread`/`pwrite` byte copy and before sealing, then writes one `O_EXCL|O_NOFOLLOW` `0600` source-snapshot artifact. It synchronizes `artifact → root → F_FULLFSYNC(artifact)`, closes write authority, appends the existing V1 sealed companion and returns a move-only process-owned continuation holding the terminal descriptor pair plus a read-only artifact FD. `DestinationStageWriter` consumes only that sealed Commit continuation and requires its destination protected root on `request.destination_parent.device`, distinct from `request.source.device`. After every cancellation probe outside the ledger mutex it revalidates the read-only source snapshot, original source and destination-parent descriptors, root binding and exact active reservation. It copies only the sealed snapshot into one canonical private `O_EXCL|O_NOFOLLOW` `0600` one-link stage, synchronizes `artifact → root → F_FULLFSYNC(artifact)`, append-seals V1 and returns only a move-only helper-private continuation with read-only stage/root descriptors. It performs no user namespace operation and exposes or exercises no publication or cleanup operation in this slice; its retained private descriptors require a separate reviewed and locked publisher gate before any future namespace mutation. V1 persists artifact seals only: source provenance and resumable continuations do not survive restart. Restart reconciliation accepts a sealed artifact only when that companion has the exact root/header/role/artifact-ID claims and its complete no-follow scalar seal exactly matches the canonical artifact; it remains read-only and cannot resume copy or publish. Missing companions, malformed manifests, and mismatched claims or seals remain retained state for a later helper-owned decision. A reservation becomes removable only after exact primary-record revalidation, directory synchronization, and proof that both its canonical artifact and sealed companion are absent. NonMAS packaging owns the target dependency, `CodeSignOnCopy` embed and reciprocal `SMPrivilegedExecutables`/`SMAuthorizedClients` requirements; Unsigned has its own plist without a privileged-helper declaration and MAS has no V1 dependency. The target configuration requires Developer ID and hardened runtime. The available machine has zero valid code-signing identities, so a signed artifact and SMJobBless trust proof remain release evidence. A concrete signed helper transport still needs a reviewed publisher that acquires protected roots and exact-revalidates source, destination, stage and destination parent with cancellation at the publication barrier, helper-only cleanup and recovery, and exact destination namespace publication. Production cross-volume selection remains closed until those parts exist.

For the current bounded lifecycle increment, a valid `ValidatedBegin` is admitted to the helper-private `LeaseStore` through `LeaseLifecycle`. Begin only retains that exact validated FD pair and mints a one-use opaque lease: it selects no root, creates no artifact and performs no namespace mutation. An exact Commit atomically consumes the lease and, until a staging executor exists, reports confirmed `NotPublished` with `HelperFailure`/`EOPNOTSUPP`; an exact Abort consumes it as `NotPublished`/`Aborted`. A malformed reply path or peer disconnect revokes the owner and closes every still-retained descriptor pair. `Granted` at this protocol boundary is deliberately not production staging availability: the production VFS client and signed transport remain absent, so `CrossVolumeStaged` is not selected and cross-volume Copy retains the legacy route.

`ProtectedRootLedger` now performs the cross-process serialization itself. It opens an exact helper-owned `0700` root-directory descriptor from the borrowed FD, locks that descriptor with nonblocking exclusive advisory `flock`, then revalidates the root identity before exposing the move-only ledger. The process-local registry remains a duplicate-owner guard and makes close-and-registry-erase indivisible with fork. Its `pthread_atfork` child handler closes inherited locked root descriptors; PID validation makes inherited ledger methods fail closed, and an attempted child acquisition against a parent-owned registry returns `ForkedProcess`. Move construction, assignment and destruction leave foreign-PID inherited ledgers inert without acquiring inherited C++ mutexes or closing a descriptor number that a child can reuse. PID binding extends through `ValidatedBegin`, `LeaseStore`, `TerminalLease`, the sealed source snapshot and the sealed destination stage. The source and destination writers reject inherited terminal/continuation input and a foreign ledger before cancellation callbacks, entering a ledger mutex or creating a reservation. This serializes only participating helpers. It neither prevents a noncooperating same-UID actor from mutating the namespace nor binds a staged inode to a future publication, and this slice exposes or exercises no publication or cleanup operation. It supersedes the earlier generic dispatcher-root locking requirement; remaining dispatcher-root work is gated acquisition and use by the future publisher.

`StagingRootAuthority` adds a detached helper-private root-admission seam. It consumes a current-process Commit `TerminalLease`, anchors two caller-borrowed root FDs, exact-validates root owner, `0700` mode and the respective source/destination-parent device binding, rejects a same-device pair, and locks the `ProtectedRootLedger` pair in canonical `(device,inode)` order. Its opaque move-only PID-bound `LockedSession` retains the terminal lease and both ledgers; failure to open the second root destroys the temporary first ledger and releases its lock. The session exposes no FD, pathname, writer, publisher, cleanup or recovery authority. Before the runner slice it was deliberately detached from the existing `SourceSnapshotWriter → DestinationStageWriter` continuation because both consume the terminal lease; the runner below now supplies only that private composition. A future publisher separately exact-revalidates and cancels at its namespace-publication barrier.

`StagingSessionRunner` now makes that helper-private composition. It consumes `LockedSession` by value, rejects a foreign or moved session before either writer callback, retains both root-ledger locks through `SourceSnapshotWriter::Create` and then `DestinationStageWriter::Create`, and preserves exact typed `Session`, `SourceSnapshot` or `DestinationStage` failure. The locks release with the consumed session on every return. Success returns only the existing move-only read-only sealed-stage continuation; it does not retain a root lock or issue any path, publisher, cleanup or recovery authority. Therefore it does not bind the stage to a future namespace operation: a publisher separately acquires and exact-revalidates root, stage and destination parent at its cancellation/publication barrier.

`StagingPublicationBarrier` is that next helper-private review gate, not a publisher. It consumes one current-process sealed destination stage, reacquires and retains the exact destination protected-root `flock`, and exact-revalidates the Commit terminal claim, source, destination parent, source snapshot, stage, primary and sealed records, canonical artifact identity and absent destination both before and after one unlocked `BeforePublication` cancellation callback. It rejects forked or moved authority, stale descriptors or manifests, a busy or mismatched root, cancellation and an existing destination. A successful opaque move-only permit retains the read-only stage and root lock but discloses neither descriptor nor pathname; `Prepare` creates, renames, links, unlinks and opens no entry in the user destination namespace. The later publisher must consume that permit to perform a separately reviewed exact atomic name binding, while helper-owned cleanup/recovery remains separate authority. The real two-device stage-to-barrier fixture is currently skipped because the available roots resolve to one device; therefore this code closure is not runtime physical-volume or publication proof.

`StagingPublicationLifecycle` adds durable retained pairing after private staging, before any publisher exists. `StagingSessionRunner` calls its private `RecordStaged` only while it retains both protected-root ledgers and only for a current-process Commit stage. The writer exact-validates the lease request, roots, source snapshot, destination stage and their sealed artifacts, rejects a same-device write scope, then writes a private immutable primary record plus sealed companion on each root in canonical order. The pair binds the header/correlation, both root identities, snapshot/stage IDs and seals, original source and destination-parent seals, and destination component. A partial write remains retained. Its separate `Inspect` reacquires both roots in canonical order and returns only `ExactPending`, `Absent`, `Incomplete`, `Mismatched` or `Malformed`; it never calls `ProtectedRootLedger::Reconcile()`, which remains the distinct artifact-record classifier. `ExactPending` requires both exact cross-bound lifecycle pairs and both exact sealed artifacts on distinct devices. The inspector exposes neither pathname nor descriptor and provides no cleanup, recovery-execution, publication or selection authority.

### Publisher design blocker

A named stage plus `renameatx_np(..., RENAME_EXCL)` cannot bind the validated staged inode to the destination name: `0700` roots, `O_NOFOLLOW`, descriptor rechecks and `flock` leave a same-UID substitution window. The available roots and test environment provide no real euid-0 signed root-isolation proof. A `VFSUT`-only characterization may demonstrate that window, but it is not a publication implementation or authority. No `StagingPublisher` API, helper authority or production selection may be introduced until either a descriptor-bound namespace primitive is available or an explicitly revised signed-root trust model has proven root acquisition and transport. Until then, `CrossVolumeStaged` remains `Unsupported` and the legacy route is retained.

**VFSUT-only characterization closed (2026-08-06):** in a test-owned `0700` root, one same-euid process no-follow-validates a `stage` descriptor and its inode, rebinds the name to retain the validated object, creates a replacement under that original name, then issues raw `renameatx_np(..., RENAME_EXCL)`. The destination contains the replacement inode and bytes, while both the retained name and original descriptor still identify the validated payload. Focused Debug passes 1 case / 48 assertions; sequential full Debug `VFSUT` records 162 / 165 cases and 46,598 / 46,601 assertions with the three established host baselines only. The test proves the namespace primitive lacks a source-inode binding; it creates no helper API, permit accessor, publisher, cleanup authority or selectable production path. It does not supply the missing signed root isolation, descriptor-bound publication primitive, physical two-volume proof, signed transport or helper cleanup/recovery authority.

## Consequences

- The generic provider transaction, mapper, execution product, orchestrator, exact run-receipt custody and durable outcome contracts can remain unchanged when the helper returns the existing tri-state result.
- The capability result distinguishes `SameVolumeClone`, `CrossVolumeStaged`, `Unsupported`, and `Unavailable`; it must not reinterpret the clone scope as staged authority.
- The helper protocol, trust boundary, helper-crash recovery, helper cleanup/recovery execution, two-internal-volume physical evidence, and a future publication design require separate implementation and review. The private lifecycle inspector supplies retained-state classification only; it does not supply cleanup or recovery execution. The private barrier supplies review-only validation/cancellation; it does not supply a publisher. Publisher work is blocked until the descriptor-bound primitive or revised signed-root trust model described above has proof.
- Until then, the existing legacy operation is the only cross-volume execution path. This preserves the stricter reviewed mutation boundary instead of treating a named temporary file as equivalent authority.

## Acceptance evidence for a future implementation

Prove helper unavailability causes zero enqueue; stage substitution by the client cannot affect publication; source/destination stale and destination-race cases fail closed; cancellation and pre-publish failures leave no visible destination; post-publish metadata/sync failures retain `Published`; helper crash returns conservative recovery evidence; helper-only bounded artifact cleanup survives restart; and the full production plan/review/journal/orchestrator path passes an opt-in two-internal-APFS-volume fixture plus final Release ASAN/UBSAN.

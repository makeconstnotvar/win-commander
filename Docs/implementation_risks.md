> Статус: local M0 baseline verified; active migration risk register
> Базовая ревизия аудита: `ec7f9f4`; mitigation status актуализирован 2026-08-02
> Связанные документы: [`win_commander_ideal_file_manager_spec.md`](win_commander_ideal_file_manager_spec.md), [`Development-Plan.md`](Development-Plan.md), [`feature_gap_matrix.md`](feature_gap_matrix.md)

## 1. Правила управления

Риск считается активным, пока mitigation подтверждён не только кодом, но и указанным evidence. Tripwire — наблюдаемое условие, после которого работа останавливается для исправления архитектурной или продуктовой границы.

Шкала:

- влияние: **critical** — риск потери данных/release blocker; **high** — ломает Alpha/Core contract; **medium** — создаёт существенный долг или деградацию;
- вероятность: **high**, **medium**, **low** относительно текущего baseline;
- владелец указывается как архитектурная область, а milestone — как крайний срок снижения риска.

## 3. Обязательные risk gates

### M1 baseline

- Определены owners и writers для app/pane/folder/selection/search/operation state.
- Зафиксированы compatibility seams: dispatcher→Registry, PanelController/PanelData→PaneStore, VFSHost→ProviderCapabilities/planner probes, `nc::Error`→FileManagerError, accepted plan→Operation/Pool→Center.
- Локальный M0 gate воспроизводит unsigned Debug build и все 10 aggregate unit binaries; hosted CI и required-check policy остаются открытыми.
- Снят воспроизводимый 10k/100k model baseline; end-to-end UI/main-thread trace обязателен до M2 rendering changes.

### До первого P0 mutation на новых contracts

- Plan создаётся и сериализуется до enqueue; execution starts only from an exact journal-bound admission receipt.
- Bound production preflight проверяет provider capability, path identity, destination и применимые destructive effects, удерживая exact bindings. Application permission composition дополняет evidence; `Accepted` проходит отдельный review/confirmation policy до factory.
- Production provider conditional transaction, typed result mapping/execution product, private factory/orchestrator integration, restricted cold hooks, exact durable-outcome delivery and run-receipt recovery are proven. Bounded `CopyAs` supplies exact app review/presentation; live boundary proof, physical-volume evidence and cross-volume staging remain separate gates.
- Fault injection покрывает source/destination/temporary-name rebind, permission revoke, disk full, metadata failure и cancel.
- Typed tri-state outcome is published atomically before Pool release; terminal-transition authority is preallocated before start; `Retain`/retry covers runtime persistence faults; `ReleaseWithoutCompletion` separates durable non-success from generic completion; reconciled residency uses `ReleaseReconciled`; post-Running pre-enqueue recovery is durable; and retained artifacts have bounded descriptor-bound authority.

### До Alpha

- Все critical/high tripwires закрыты либо имеют явно принятый release blocker.
- Commander и Explorer проходят общий regression slice.
- Large-folder, accessibility, persistence/recovery, permission и visual-state evidence приложены к gate.
- Нет silent failures, direct UI/VFS mutations и неразъяснимых disabled actions.

## 4. Порядок снижения рисков

При конфликте сроков порядок жёсткий: data safety → correctness/state ownership → responsiveness → visual/error transparency → accessibility → feature breadth. Оптимизация количества surfaces до стабилизации boundary tests является ложной экономией: она размножает несовместимые entry points и увеличивает стоимость каждого последующего исправления.

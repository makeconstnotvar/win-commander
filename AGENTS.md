## Architecture and safety boundaries

- Application and Explorer integration live in `Source/WinCommander/WinCommander`, especially `States/`, `States/Explorer/`, and `Core/{Commands,Pane,Errors,VisualState}`. Reuse the established `Source/{Base,Config,CUI,Operations,Panel,RoutedIO,Term,Utility,VFS,VFSIcon,Viewer}` engines through narrow contracts and adapters.
- `PanelController` owns stable pane identity and navigation/refresh lifecycle. `PaneStore` accepts committed results only after exact request validation. Focus is republished after cursor restoration; selection uses exact shared item identities cached by the Model selection generation. Hidden-file, sort, grouping, actual view mode, valid layout-slot, Back/Forward availability and runtime current History entry identity exist before listing load; lifecycle overlays preserve them. Explorer command presentation accepts only its matching snapshot and fails closed before one arrives. Up/Refresh toolbar availability is derived from that matching snapshot, while execution always rechecks the live controller. Async navigation runs a detached fetch on a shared `SerialQueue`; worker/main callbacks retain only a weak controller box, intent invalidation cancels the worker token, and controller deallocation stops without waiting for a non-cooperative provider. Persistency recovery callbacks are weak.
- `Core/Commands/CommandIds.h` defines eleven stable IDs. The app-owned Registry routes all eleven production definitions: Copy, Cut, Rename initiation, `file.open`, `view.toggleHiddenFiles`, Back, Forward, explicit Up, forced user Refresh, `operation.cancel` and `operationCenter.open`. `operationCenter.open` obtains a weak-coordinator value snapshot, copies it again at the Registry boundary, and calls a borrowed synchronous Explorer presenter for a bounded static panel with active and terminal/interrupted records plus Registry-gated Cancel; reopening is its explicit refresh. `file.open` is the shared route for `OnOpenNatively:`/menu, the ordinary-file fallback of Enter, Shift-Return/explicit Shortcut, and context-menu exact-item payloads. One regular file is eligible on a readable provider; a batch requires regular files from the exact same readable provider instance; native directory/special-item handoff is supported, while dot-dot and remote directory/special-item handoff fail closed. Enter remains the router for folder/archive navigation and terminal execution. The executor synchronously hands the accepted items to `FileOpener`; Registry `Executed` means submitted handoff, not completion by Launch Services or a remote opener. Non-uniform dot-dot/Enter navigation retains its legacy Back fallback, and dot-dot submits exactly one enclosing-folder request. Explicit Up accepts uniform child/provider-parent navigation. The secondary Up shortcut preserves its menu bounce, and command-aware alias matching classifies that invocation as Shortcut. Automatic soft refresh remains outside the Registry. Rename commit still uses the established `nc::ops::Copying(docopy = false)` operation; Back/Forward execution still submits the legacy `ListingPromiseLoader` task after the live History guard.
- The M3 chain is `OperationPlan → bound preflight → explicit review → journal admission → execution construction → Pool → durable terminal journal state`. Planning, review, journal receipts, construction, enqueue, provider commit, and terminal persistence are separate authorities.
- Provider conditional Copy transactions are provider-minted, move-only, single-use, and expose typed abort plus tri-state publication evidence. A private-constructible `ProviderConditionalCopyReviewedAuthority` consumes and retains the exact reviewed preflight, exposes immutable semantic claims, and cannot be issued twice from the moved review token. `ProviderConditionalCopyPathSupport` distinguishes `SameVolumeClone` from the future `CrossVolumeStaged` scope. Native implements the ADR 0001 clone-only scope for one regular file on the exact same `NativeHost` and internal, local, writable APFS volume with known permission, clone, attribute, xattr, and extended-security support. Begin anchors source and destination-parent descriptors and seals their identities and exact supported metadata. Commit receives a borrowed synchronous cancellation checker, resamples it before the clone publication barrier, revalidates every seal, publishes exclusively through `fclonefileat(..., CLONE_ACL)`, verifies destination metadata and name identity, then orders `fsync(destination) → fsync(parent) → F_FULLFSYNC(destination)`. Post-publication metadata or filesystem-sync failures remain `Published` with independent typed evidence. The ADR 0002 Native seam passes only anchored source/destination-parent FDs, a single destination component and complete scalar seals to an injected authority. Its private client creates the V1 claim, duplicates only those two FDs into a fakeable transport, accepts only validated matching replies, maps post-dispatch uncertainty to `Unknown` and samples cancellation before Begin, after Granted and before Commit dispatch. `CrossVolumeStaged` remains `Unsupported`/legacy until a signed helper transport is installed. `RoutedIO/CrossVolumeStagingProtocol` defines helper-specific V1 claims, opaque lease and conservative completion independently of VFS and the legacy generic helper; its private codec owns two duplicated descriptor rights plus strict request/reply grammar. `CrossVolumeStagingHelperV1` authenticates the signed peer before decode, makes both received FDs close-on-exec/read-only and exact-revalidates the complete scalar source/destination-parent seals into a move-only private `ValidatedBegin`. It reports invalid claims, stale source/parent and helper failure with typed Begin rejection; valid claims remain inert `Unsupported`. Its fixed-capacity private `LeaseStore` accepts only `ValidatedBegin`, mints 256-bit tokens with `SecRandomCopyBytes`, binds each active correlation to its authenticated owner and retains the validated FDs through exactly one terminal take or owner revoke. Any future execution must revalidate the exact FDs at its publication barrier. Its `ProtectedRootLedger` accepts a root-owned exact-`0700` root FD, owns each sealed root once per process, makes a `0600` root/correlation/role/artifact-ID manifest durable before exposing it, and classifies sealed artifacts read-only only when complete root/header/role/artifact-ID claims and their full no-follow scalar seal match. The classifier retains sealed, absent, incomplete, malformed and mismatched states; a reservation becomes removable only after exact manifest revalidation and proof that its canonical artifact name is absent. Artifact materialization, cleanup, dispatcher-root acquisition and namespace staging are future mutable authority. NonMAS alone owns the target dependency and `CodeSignOnCopy` embedding; the target requires Developer ID and hardened runtime. Production keeps the VFS client and transport absent, so cross-volume uses the legacy route. Native keeps an untransferred granted lease RAII-owned until generic mint succeeds. A present but unavailable authority reports `Unavailable` and cannot be selected. No journal recovery path receives staging cleanup authority.
- `CopyOperationOrchestrator` has a production constructor over journal, `Pool`, and `CopyOperationRunReceiptCustodian`; injected construction is test-only. Its private reviewed-factory path returns a sealed move-only execution product. Admission precedes construction; restricted lifecycle/item-status hooks are installed while the operation is cold; a bounded plan/storage slot precedes Running; and accepted enqueue transfers the exact receipt slot to the Pool finalizer. An owning durable outcome is delivered at most once after exact finalization or reconciliation. Pre-rename failure retains exact `Finalize` retry authority. Post-rename uncertainty drops live authority: a same-storage reopen performs read-only `Reconcile`, then `ReleaseReconciled` probes and releases the exact Pool residency.
- The bounded production `CopyAs` consumer composes exact plan/preflight/review with process-owned journal, custodian and recovery coordination, the private reviewed factory, window `Pool`, item-status presentation and owning durable outcomes. Production selects only explicit path-specific `SameVolumeClone`; `CrossVolumeStaged` remains conditional on the separately signed authority. Unavailable evidence and every failure after reviewed selection fail closed. Known unsupported shapes retain the legacy operation. The window submission gate prevents teardown races.
- Provider conditional Copy results map losslessly into journal evidence, and the transaction-backed Job owns the single commit/stop/destruction gate, including worker-launch failure. `Pool` preallocates accepted terminal-transition authority; durable failure, cancellation, and interruption release through `ReleaseWithoutCompletion`, preserving removal and next-start semantics while suppressing generic completion. Public compatibility `ReviewedOperationFactory::Create` deliberately aborts and fails closed; only its private orchestrator friend path can construct the runnable product. Cross-volume support still requires provider-owned bounded staging. Existing production mutations remain on established operations.

## Working rules

1. Read the relevant canonical-spec section and active development-plan item before editing.
2. Deliver the smallest vertical contract slice and preserve Commander behavior, responder precedence, provider semantics, user data, upstream notices, and unrelated work.
3. Keep mutation execution fail closed. Blocked, stale, cancelled, unsupported, unpersisted, or insufficiently bound intent never reaches `Pool`.
4. Use the verification budget below. Expand checks by risk and dependency impact, not as a fixed ladder after every edit.
5. Document a closed slice with one `changelog.md` line plus the updated status cell in `Docs/Development-Plan.md`. Put detailed evidence in the slice feature-spec, not in the plan. Update architecture/build/user docs only when the slice changes what they describe. Separate implemented behavior from target behavior.
6. Queue 1 slices implement product surface over the existing `nc::ops::*` operations and the established Registry/Store/Capabilities/Error/Visual State contracts. Do not extend the reviewed operation engine, cross-volume staging or physical/power-loss evidence during Queue 1; see `Docs/Development-Plan.md` sections 3.1 and 5.1.

## Implementation and verification budget

- Spend the default context and execution budget on functional implementation: complete working UI or behavior before broad audits. Read only the relevant spec/plan sections, parallelize independent discovery and long gates, and update affected docs/changelog once at slice closure. During iteration, batch related edits behind a stable seam and run the smallest focused test filter that exercises the changed contract. Run an affected unsigned Debug build once when the slice stabilizes; a focused build/test that compiles the changed pure-logic target is sufficient during the inner loop.
- Treat successful evidence as valid while its production dependencies, tests, build configuration, toolchain and fixtures remain unchanged. A later edit invalidates only the evidence whose dependency surface it touches. Documentation, changelog and ordinary formatting after a successful code gate preserve that gate.
- Run the full affected test binary once at slice closure for shared/public APIs, Registry/Store/VFS adapters, lifecycle, persistence, provider semantics or broad transitive changes. Run aggregate `UnitTests`, `verify_m0.sh`, full integration profiles and performance/accessibility matrices at milestone, merge or release gates, after build-system/toolchain changes, or when focused evidence indicates cross-module regression.
- Preserve the mutation closure gate for every slice: focused fail-closed tests plus the full affected Debug suite. Run explicit Release ASAN/UBSAN only when `Operations`, `VFS`, `RoutedIO`, transaction, journal, codec, `Pool`, raw buffers, async teardown, concurrency, ownership or lifetime code changes. AppKit, Registry, `PaneStore` and presentation slices need a focused filter plus one Debug build, not sanitizer runs. Run physical, remote, permission, restart and container fixtures when that capability changes or its queue closes.
- After a failure, rerun the failed test while diagnosing and the original focused set after the fix. Record an unrelated baseline failure once with its scope and continue the slice; broader regression work starts only when the failure intersects the changed dependency surface.
- For documentation-only work, run `git diff --check` plus link/path/command consistency checks. For test-only work, run the modified test target. For format-only work, inspect the semantic diff and run a build only when macros, generated sources or project metadata are involved.
- Choose the verification level before implementation and expand it only when risk grows or evidence exposes a defect. Record concise new evidence: command scope, configuration, result, relevant cases/assertions, sanitizer runtime and required fixtures. Keep previous aggregate results labelled as baselines and refresh only the counters actually executed for the current slice.

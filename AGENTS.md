## Architecture and safety boundaries

- Application and Explorer integration live in `Source/WinCommander/WinCommander`, especially `States/`, `States/Explorer/`, and `Core/{Commands,Pane,Errors,VisualState}`. Reuse the established `Source/{Base,Config,CUI,Operations,Panel,RoutedIO,Term,Utility,VFS,VFSIcon,Viewer}` engines through narrow contracts and adapters.
- `PanelController` owns stable pane identity and navigation/refresh lifecycle. `PaneStore` accepts committed results only after exact request validation. Focus is republished after cursor restoration; selection uses exact shared item identities cached by the Model selection generation. Hidden-file, sort, grouping, actual view mode, valid layout-slot, Back/Forward availability and runtime current History entry identity exist before listing load; lifecycle overlays preserve them. Explorer command presentation accepts only its matching snapshot and fails closed before one arrives. Up/Refresh toolbar availability is derived from that matching snapshot, while execution always rechecks the live controller. Async navigation runs a detached fetch on a shared `SerialQueue`; worker/main callbacks retain only a weak controller box, intent invalidation cancels the worker token, and controller deallocation stops without waiting for a non-cooperative provider. Persistency recovery callbacks are weak.
- `Core/Commands/CommandIds.h` defines eleven stable IDs. The app-owned Registry currently routes nine production definitions: Copy, Cut, Rename initiation, `file.open`, `view.toggleHiddenFiles`, Back, Forward, explicit Up and forced user Refresh. `file.open` is the shared route for `OnOpenNatively:`/menu, the ordinary-file fallback of Enter, Shift-Return/explicit Shortcut, and context-menu exact-item payloads. One regular file is eligible on a readable provider; a batch requires regular files from the exact same readable provider instance; native directory/special-item handoff is supported, while dot-dot and remote directory/special-item handoff fail closed. Enter remains the router for folder/archive navigation and terminal execution. The executor synchronously hands the accepted items to `FileOpener`; Registry `Executed` means submitted handoff, not completion by Launch Services or a remote opener. Non-uniform dot-dot/Enter navigation retains its legacy Back fallback, and dot-dot submits exactly one enclosing-folder request. Explicit Up accepts uniform child/provider-parent navigation. The secondary Up shortcut preserves its menu bounce, and command-aware alias matching classifies that invocation as Shortcut. Automatic soft refresh remains outside the Registry. Rename commit still uses the established `nc::ops::Copying(docopy = false)` operation; Back/Forward execution still submits the legacy `ListingPromiseLoader` task after the live History guard.
- The M3 chain is `OperationPlan → bound preflight → explicit review → journal admission → execution construction → Pool → durable terminal journal state`. Planning, review, journal receipts, construction, enqueue, provider commit, and terminal persistence are separate authorities.
- Provider conditional Copy transactions are provider-minted, move-only, single-use, and expose typed abort plus tri-state publication evidence. A private-constructible `ProviderConditionalCopyReviewedAuthority` consumes and retains the exact reviewed preflight, exposes immutable semantic claims, and cannot be issued twice from the moved review token. Native implements the ADR 0001 clone-only scope for one regular file on the exact same `NativeHost` and internal, local, writable APFS volume with known permission, clone, attribute, xattr, and extended-security support. Begin anchors source and destination-parent descriptors and seals their identities and exact supported metadata. Commit revalidates every seal, publishes exclusively through `fclonefileat(..., CLONE_ACL)`, verifies destination metadata and name identity, then orders `fsync(destination) → fsync(parent) → F_FULLFSYNC(destination)`. Post-publication metadata or filesystem-sync failures remain `Published` with independent typed evidence. Other provider/volume scopes return `Unsupported`.
- `CopyOperationOrchestrator` has a production constructor over journal, `Pool`, and `CopyOperationRunReceiptCustodian`; injected construction is test-only. Its private reviewed-factory path returns a sealed move-only execution product. Admission precedes construction; a bounded plan/storage slot precedes Running; the exact receipt is armed before enqueue; and accepted enqueue transfers the same slot to the Pool finalizer. Pre-rename failure retains exact `Finalize` retry authority. Post-rename uncertainty drops live authority: a same-storage reopen performs read-only `Reconcile`, then `ReleaseReconciled` probes and releases the exact Pool residency. No app mutation consumer is connected yet.
- Provider conditional Copy results map losslessly into journal evidence, and the transaction-backed Job owns the single commit/stop/destruction gate, including worker-launch failure. Public compatibility `ReviewedOperationFactory::Create` deliberately aborts and fails closed; only its private orchestrator friend path can construct the runnable product. Cross-volume support still requires provider-owned bounded staging. Existing production mutations remain on established operations.

## Working rules

1. Read the relevant canonical-spec section and active development-plan item before editing.
2. Deliver the smallest vertical contract slice and preserve Commander behavior, responder precedence, provider semantics, user data, upstream notices, and unrelated work.
3. Keep mutation execution fail closed. Blocked, stale, cancelled, unsupported, unpersisted, or insufficiently bound intent never reaches `Pool`.
4. Verify focused tests, affected builds, then aggregate and sanitizer gates proportional to risk. Record only executed evidence; signing and provider fixtures require their documented environments.
5. Update the development plan, changelog, and affected architecture/build/user docs in the same slice. Separate implemented behavior from target behavior.
